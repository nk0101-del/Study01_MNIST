# 손글씨 인식기 웹/데스크톱 분리 설계

작성일: 2026-09-26

## 1. 목적과 범위

하나의 저장소에서 같은 CNN을 두 경로로 제공한다.

- **데스크톱 버전** — 기존 PyTorch + Tkinter 코드. 내용 변경 없이 `desktop_version/` 으로 이동한다. 학습의 유일한 주체이며, 웹이 쓸 가중치를 산출한다.
- **웹 버전** — `web_version/` 에 새로 작성한다. 외부 라이브러리 없이 순수 자바스크립트로만 추론하고, 빌드 단계 없이 GitHub Pages에 정적으로 배포된다.

두 버전은 코드를 공유하지 않는다. 유일한 연결 고리는 데스크톱이 내보낸 가중치 파일이다.

### 성공 기준

1. 같은 숫자를 웹과 데스크톱에 그렸을 때 같은 숫자를 예측한다.
2. `검증.html` 이 20개 사례 전부에 대해 합격을 보고한다 (기준은 7.2절).
3. GitHub Pages URL에서 빌드 단계 없이 동작한다.
4. 웹 버전이 런타임에 어떤 외부 스크립트도 내려받지 않는다.

### 범위 밖

- 웹에서의 학습. 학습은 데스크톱 전용이다.
- 웹에서의 이미지 파일 업로드 인식. 입력 경로는 그리기 하나뿐이다.
- 모델 구조 변경, 정확도 개선, 추론 속도 최적화.
- Windows 실행 파일 패키징.

## 2. 최종 폴더 구조

```
Study01_MNIST/
├─ CLAUDE.md                     # 다시 씀 — 두 버전 안내 + 공통 규칙
├─ README.md                     # 다시 씀 — 두 버전 안내
├─ .gitignore                    # 수정 — 검증 데이터 제외 규칙 추가
├─ .github/workflows/pages.yml   # 신규 — web_version/ 을 Pages로 배포
├─ docs/superpowers/specs/       # 이 문서
├─ desktop_version/
│  ├─ CLAUDE.md                  # 신규 — 기존 CLAUDE.md 내용 대부분이 여기로
│  ├─ model.py                   # 이동 (내용 변경 없음)
│  ├─ train.py                   # 이동 (내용 변경 없음)
│  ├─ preprocess.py              # 이동 (내용 변경 없음)
│  ├─ draw_app.py                # 이동 (내용 변경 없음)
│  ├─ predict.py                 # 이동 (내용 변경 없음)
│  ├─ mnist_cnn.pt               # 이동 (gitignore 대상)
│  ├─ data/                      # 이동 (gitignore 대상)
│  ├─ 가중치내보내기.py           # 신규
│  └─ 검증데이터만들기.py         # 신규
└─ web_version/
   ├─ CLAUDE.md                  # 신규
   ├─ index.html
   ├─ 스타일.css
   ├─ 그림판.js                  # 캔버스 그리기 (마우스 + 터치)
   ├─ 전처리.js                  # preprocess.py 이식
   ├─ 모델.js                    # 가중치 적재 + 순전파
   ├─ 앱.js                      # 위 셋을 엮어 결과 표시
   ├─ 가중치.bin                 # 산출물 약 4.6MB — 커밋한다

   ├─ 검증데이터.json            # 산출물 — gitignore 대상
   └─ 검증.html                  # 파이썬 결과와 대조하는 검증 페이지
```

파이썬 파일 이동은 `git mv` 로 수행해 이력을 보존한다. 다섯 파일 모두 같은 폴더에 함께 이동하므로 상대 임포트(`from model import MnistCNN` 등)는 수정할 필요가 없다.

`.gitignore` 의 기존 규칙 `data/` 와 `*.pt` 는 하위 폴더에도 그대로 적용되므로 이동한 파일들은 계속 제외된다. `가중치.bin` 은 어떤 기존 규칙에도 걸리지 않으므로 그대로 커밋된다. 추가할 규칙은 `web_version/검증데이터.json` 한 줄이다.

## 3. 문서 3개의 역할 분담

| 파일 | 담는 내용 | 담지 않는 내용 |
| --- | --- | --- |
| 루트 `CLAUDE.md` | 한글 이름 관례, 두 폴더의 관계, 가중치가 유일한 연결 고리라는 사실, 폴라리티/정규화 불변식 | 각 버전의 세부 실행법 |
| `desktop_version/CLAUDE.md` | 기존 CLAUDE.md 의 PyTorch 내용, `state_dict` 키 주의, 학습·실행 명령, 내보내기 절차 | 자바스크립트 관련 내용 |
| `web_version/CLAUDE.md` | 순수 JS 제약, `.bin` 레이아웃 계약, 전처리 이식 주의점, `file://` 문제, Pages 배포 | 파이썬 관련 내용 |

하위 폴더 `CLAUDE.md` 는 해당 폴더의 파일을 다룰 때 로드되고 루트는 항상 로드된다. 따라서 공통 사항은 루트에만 두고 하위에서 반복하지 않는다.

## 4. 가중치 전달 계약

이 계약이 두 버전을 잇는 유일한 인터페이스이므로 양쪽 CLAUDE.md 에 명시적으로 기록한다.

### 4.1 `가중치.bin`

8개 텐서를 아래 순서로 float32 리틀엔디언으로 연속 기록한다. 헤더도 구분자도 없다.

| 순서 | 텐서 | 형상 | 개수 | 시작(float 단위) |
| --- | --- | --- | --- | --- |
| 1 | `합성곱1.weight` | [32, 1, 3, 3] | 288 | 0 |
| 2 | `합성곱1.bias` | [32] | 32 | 288 |
| 3 | `합성곱2.weight` | [64, 32, 3, 3] | 18432 | 320 |
| 4 | `합성곱2.bias` | [64] | 64 | 18752 |
| 5 | `완전연결1.weight` | [128, 9216] | 1179648 | 18816 |
| 6 | `완전연결1.bias` | [128] | 128 | 1198464 |
| 7 | `완전연결2.weight` | [10, 128] | 1280 | 1198592 |
| 8 | `완전연결2.bias` | [10] | 10 | 1199872 |

합계 1,199,882개 = 4,799,528바이트(약 4.6MB). 각 텐서 내부의 원소 순서는 PyTorch 의 C 연속(row-major) 순서를 그대로 따른다.

엔디언은 `astype("<f4")` 로 명시한다. 플랫폼 기본값에 의존하지 않는다.

### 4.2 `가중치정보.json`

```json
{
  "정규화": { "평균": 0.1307, "표준편차": 0.3081 },
  "텐서들": [
    { "이름": "합성곱1.weight", "형상": [32, 1, 3, 3], "시작": 0, "개수": 288 }
  ]
}
```

`모델.js` 는 4.1의 표를 하드코딩하지 않고 이 파일을 읽어 `.bin` 을 잘라 쓴다. 정규화 상수도 여기서 흘러나오므로 자바스크립트에 다시 하드코딩하지 않는다. 이로써 `평균`/`표준편차` 중복은 파이썬 쪽 두 곳(`train.py`, `preprocess.py`)에 그대로 남고 웹으로는 번지지 않는다.

### 4.3 평탄화 순서

PyTorch `x.flatten(1)` 은 (64, 12, 12) 텐서를 채널 우선으로 편다. 자바스크립트도 반드시 같은 식을 써야 한다.

```
색인 = 채널 * 144 + 세로 * 12 + 가로
```

이 순서가 틀리면 오류 없이 예측만 무의미해진다. 검증이 잡아내는 대표적 오류다.

## 5. 데스크톱 신규 스크립트

### 5.1 `가중치내보내기.py`

```
python 가중치내보내기.py [--가중치 mnist_cnn.pt] [--출력폴더 ../web_version]
```

1. `torch.load(..., map_location="cpu")` 로 `state_dict` 를 읽는다.
2. 기대하는 8개 키가 모두 있는지 확인한다. 하나라도 없으면 어떤 키를 찾았고 무엇을 기대했는지 보여 주며 중단한다. 계층 이름을 바꿔 체크포인트가 무효가 된 상황을 조용한 오작동이 아니라 명시적 오류로 드러내기 위함이다.
3. 각 텐서의 형상이 4.1의 표와 일치하는지 확인한다.
4. `가중치.bin` 과 `가중치정보.json` 을 쓴다.
5. 기록한 텐서 수, 총 파라미터 수, 파일 크기를 출력한다.

### 5.2 `검증데이터만들기.py`

```
python 검증데이터만들기.py [--개수 20] [--출력 ../web_version/검증데이터.json]
```

MNIST 테스트셋 앞에서 지정 개수만큼 가져와, 각 사례마다 다음을 기록한다.

| 항목 | 만드는 법 | 검증에서의 용도 |
| --- | --- | --- |
| `원본PNG` | 28×28 을 NEAREST 로 280×280 확대 후 무손실 PNG → base64 | 자바스크립트가 동일한 화소에서 출발하게 함 |
| `중간28x28` | `전처리` 의 축소·중심정렬 직후 정수 784개 | `전처리.js` 의 정답 |
| `전처리출력` | `전처리` 의 최종 실수 784개 | 정규화까지 확인 |
| `로짓` | 모델 순전파 결과 실수 10개 | `모델.js` 의 정답 |
| `예측` | 로짓의 argmax | 최종 결과 확인 |

280×280 으로 확대하는 이유는 실제 캔버스 입력과 같은 크기에서 축소 경로(LANCZOS)를 실제로 거치게 하기 위함이다. NEAREST 확대는 정보를 더하지 않으므로 원본 화소값이 그대로 보존된다.

`중간28x28` 을 따로 기록하는 것이 이 설계의 핵심이다. 덕분에 `전처리.js` 와 `모델.js` 를 서로 독립적으로 검증할 수 있고, 불일치가 났을 때 어느 쪽 문제인지 즉시 구분된다.

이 스크립트는 `preprocess.py` 의 `전처리` 를 그대로 호출한다. 중간값을 얻기 위해 `preprocess.py` 에 선택적 반환 인자를 더할지는 구현 계획에서 정한다. 어떤 방식이든 기존 호출부(`draw_app.py`, `predict.py`)의 동작은 바뀌지 않아야 한다.

## 6. 웹 버전 구성 요소

네 파일이 각각 하나의 일만 하고 ES 모듈로 값만 주고받는다. 전역 변수를 공유하지 않는다.

### 6.1 `전처리.js`

```
전처리(명도배열, 너비, 높이, 정규화상수) → { 중간: Uint8Array(784), 출력: Float32Array(784) } | null
```

`preprocess.py` 를 단계별로 그대로 옮긴다.

1. 0이 아닌 화소의 경계 상자를 찾는다 (PIL `getbbox()` 상당). 없으면 `null` 을 돌려준다.
2. 잘라낸 영역을 가로세로 비율을 유지하며 긴 변이 20px이 되도록 LANCZOS로 축소한다.
3. 28×28 검은 바탕 중앙에 붙인다.
4. 명도를 무게로 보아 무게중심을 구하고 (13.5, 13.5)로 정수만큼 평행이동한다. 바깥은 0으로 채운다.
5. `(값 / 255 - 평균) / 표준편차` 로 정규화한다.

중간 단계인 4번 직후의 28×28 정수 배열을 함께 돌려주는 이유는 `검증.html` 이 축소·정렬 단계만 따로 대조할 수 있게 하기 위함이다.

축소는 일반적인 Lanczos 가 아니라 **PIL 이 실제로 쓰는 계수 계산**을 따라야 한다. 구체적으로 축소 시 필터 지원 범위를 배율만큼 넓히고, 각 출력 화소마다 계수 합이 1이 되도록 정규화한 뒤, 결과를 0~255로 반올림·클립한다. 이 단계가 웹 버전에서 가장 미묘한 부분이며 검증의 `중간28x28` 이 정확히 이 지점을 겨냥한다.

### 6.2 `모델.js`

```
모델불러오기(가중치정보URL, 가중치URL) → { 추론, 정규화상수 }
추론(입력784) → Float32Array(10)
```

`가중치정보.json` 을 읽고 `가중치.bin` 을 `ArrayBuffer` 로 받아 텐서별 `Float32Array` 뷰로 자른다. 순전파는 `model.py` 의 `forward` 와 같은 순서로 수행하고 드롭아웃은 건너뛴다(추론 모드).

연산은 소박한 중첩 루프로 구현한다. 전체 연산량이 약 1,200만 MAC이므로 브라우저에서 수 밀리초면 끝난다. 최적화는 넣지 않는다.

### 6.3 `그림판.js`

280×280 캔버스에 검은 배경·흰 선, 선굵기 18로 그린다. 데스크톱 `draw_app.py` 와 같은 값이다.

- Pointer Events 하나로 마우스·터치·펜을 모두 받는다.
- 캔버스는 CSS로 화면 폭에 맞춰 축소하되 **내부 해상도는 280으로 고정**하고, 포인터 좌표를 `getBoundingClientRect()` 비율로 변환한다. 이 변환을 빠뜨리면 큰 화면에서는 정상인데 좁은 화면에서만 선이 어긋난다.
- 캔버스에 `touch-action: none` 을 지정해 그리는 동안 페이지가 스크롤되지 않게 한다.
- 포인터를 떼면 인식 콜백을 호출한다 (`draw_app.py` 의 동작과 동일).

### 6.4 `앱.js`

위 셋을 엮고 화면을 갱신한다. 모델과 전처리의 내부는 모른다.

```
포인터 입력 → 280×280 캔버스
  → getImageData → 명도 배열
  → 전처리.js → Float32Array(784)
  → 모델.js 추론 → 로짓 10개
  → 소프트맥스 → 상위 3개 후보 표시
```

소프트맥스는 최댓값을 빼는 수치 안정 방식으로 계산한다.

## 7. 검증

### 7.1 `검증.html`

`검증데이터.json` 을 읽어 사례마다 두 갈래를 독립적으로 돌린다.

- **전처리 갈래** — `원본PNG` 를 캔버스로 디코딩(무손실이므로 화소가 정확히 일치) → `전처리.js` → `중간28x28` 및 `전처리출력` 과 비교
- **모델 갈래** — `전처리출력` 을 그대로 `모델.js` 에 넣어 → `로짓` 과 비교

결과를 사례별 표(`28×28 일치` / `전처리 최대오차` / `로짓 최대오차` / `예측 일치`)와 전체 합격·불합격 요약으로 보여 준다. 외부 라이브러리 없이 DOM 조작만 쓴다.

### 7.2 합격 기준

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| `중간28x28` | 784개 전부 완전 일치 | PIL 이 정수로 반올림하므로 이식이 옳다면 비트 단위로 같아야 한다. ±1만 나와도 축소 이식이 틀렸다는 뜻이다 |
| `전처리출력` | 최대 절대오차 < 1e-4 | 28×28이 같다면 남는 차이는 float32 대 float64 뿐이며 1e-7 수준이다 |
| `로짓` | 최대 절대오차 < 1e-3 | 누적 부동소수점 오차를 감안한 여유값 |
| `예측` | 20개 전부 일치 | 최종 사용자가 보는 결과 |

### 7.3 검증 데이터를 커밋하지 않는 이유

검증은 개발 시점 활동이고 최종 사용자에게 필요 없다. `검증데이터.json` 은 `.gitignore` 대상이며, 따라서 **`검증.html` 은 GitHub Pages 에서는 동작하지 않고 로컬에서만 동작한다.** 파일이 없을 때는 `python 검증데이터만들기.py` 를 먼저 실행하라는 안내를 표시한다.

## 8. 오류 처리

조용한 실패를 만들지 않는 데 초점을 둔다.

| 상황 | 동작 |
| --- | --- |
| `가중치.bin` 또는 `가중치정보.json` 적재 실패 | 그리기를 막고 한글 안내 표시 |
| `가중치정보.json` 의 총 개수 × 4 ≠ `.bin` 바이트 수 | 즉시 오류. 두 산출물이 어긋난 채 동작하는 상황을 차단한다 |
| `file://` 로 연 경우 | `fetch` 가 막히므로 이를 감지해 `python -m http.server` 로 열라고 안내한다 |
| 빈 그림 | `전처리` 가 `null` → "먼저 숫자를 그려 주세요" |
| `검증데이터.json` 없음 | `python 검증데이터만들기.py` 실행 안내 |

`file://` 안내는 필수다. 로컬에서 `index.html` 을 더블클릭하면 반드시 실패하는데 원인이 화면에 드러나지 않으면 막힌다.

## 9. 배포

`.github/workflows/pages.yml` 이 `main` 브랜치 푸시 때 `web_version/` 을 그대로 Pages 에 올린다. `actions/configure-pages` → `actions/upload-pages-artifact` (`path: web_version`) → `actions/deploy-pages` 순서이며 빌드도 npm 도 없다. 권한은 `pages: write`, `id-token: write` 를 준다.

**사람이 한 번 해야 하는 설정**: 저장소 Settings → Pages → Source 를 "GitHub Actions" 로 변경. 이 단계는 자동화할 수 없으므로 README 에 적고 구현 완료 시 다시 안내한다.

## 10. 구현 순서

검증이 먼저 자리잡도록 배치한다.

1. `git mv` 로 파이썬 5개 파일 이동, 실행 확인
2. `가중치내보내기.py` → `가중치.bin`, `가중치정보.json` 산출
3. `검증데이터만들기.py` → `검증데이터.json` 산출
4. `모델.js` + `검증.html` 의 모델 갈래 → 로짓 일치 확인
5. `전처리.js` + `검증.html` 의 전처리 갈래 → 28×28 완전 일치 확인
6. `그림판.js`, `앱.js`, `index.html`, `스타일.css`
7. `CLAUDE.md` 3개, `README.md`, `.gitignore`, `pages.yml`

4번과 5번에서 각 자바스크립트 모듈은 완성 직후 파이썬 기준과 대조된다. 나중에 한꺼번에 맞추려 하면 어느 단계가 틀렸는지 분리하기 어려워진다.

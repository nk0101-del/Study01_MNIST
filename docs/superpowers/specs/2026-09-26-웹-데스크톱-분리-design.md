# 손글씨 인식기 웹/데스크톱 분리 설계

작성일: 2026-09-26

## 1. 목적과 범위

하나의 저장소에서 같은 CNN을 두 경로로 제공한다.

- **데스크톱 버전** — 기존 PyTorch + Tkinter 코드. 내용 변경 없이 `desktop_version/` 으로 이동한다. 학습의 유일한 주체이며, 웹이 쓸 가중치를 산출한다.
- **웹 버전** — `web_version/` 에 새로 작성한다. 외부 라이브러리 없이 순수 자바스크립트로만 추론하고, 빌드 단계 없이 GitHub Pages에 정적으로 배포된다.

두 버전은 코드를 공유하지 않는다. 유일한 연결 고리는 데스크톱이 내보낸 가중치 파일이다.

ONNX 같은 공용 형식으로 변환하지 않는다. 가중치를 직접 내보내고 순전파를 자바스크립트로 다시 작성한다. 런타임 의존성이 0이 되고, 모델 구조가 작아 다시 쓰는 비용이 변환 도구를 들이는 비용보다 작기 때문이다.

### 성공 기준

| 항목 | 기준 |
| --- | --- |
| 순전파 일치 | 같은 28×28 입력에 대한 확률 10개의 최대 절대차 ≤ 1e-4 |
| 전체 정확도 | 검증 표본에서 97% 이상이고, 파이썬 정확도보다 1%p 넘게 낮지 않을 것 |
| 데스크톱 회귀 | 이동 후에도 `train.py`, `draw_app.py`, `predict.py` 가 정상 동작 |
| 웹 앱 동작 | 그린 숫자를 인식하고 상위 3개 후보를 표시 |
| 의존성 | 웹 버전이 런타임에 외부 스크립트를 내려받지 않음 |

### 범위 밖

- 웹에서의 학습. 학습은 데스크톱 전용이다.
- 웹에서의 이미지 파일 업로드 인식. 입력 경로는 그리기 하나뿐이다.
- 모델 구조 변경, 정확도 개선, 추론 속도 최적화.
- Windows 실행 파일 패키징.

## 2. 최종 폴더 구조

```
Study01_MNIST/
├─ CLAUDE.md                     # 다시 씀 — 두 버전 안내 + 공통 규칙
├─ README.md                     # 다시 씀 — 두 버전 안내
├─ .gitignore                    # 수정 — 검증 데이터 제외 규칙 추가
├─ .github/workflows/pages.yml   # 신규 — web_version/ 을 Pages로 배포
├─ docs/superpowers/specs/       # 이 문서
├─ desktop_version/
│  ├─ CLAUDE.md                  # 신규 — 기존 CLAUDE.md 내용 대부분이 여기로
│  ├─ model.py                   # 이동 (내용 변경 없음)
│  ├─ train.py                   # 이동 (내용 변경 없음)
│  ├─ preprocess.py              # 이동 (내용 변경 없음)
│  ├─ draw_app.py                # 이동 (내용 변경 없음)
│  ├─ predict.py                 # 이동 (내용 변경 없음)
│  ├─ mnist_cnn.pt               # 이동 (gitignore 대상)
│  ├─ data/                      # 이동 (gitignore 대상)
│  ├─ 가중치내보내기.py           # 신규
│  └─ 검증데이터만들기.py         # 신규
└─ web_version/
   ├─ CLAUDE.md                  # 신규
   ├─ index.html
   ├─ 스타일.css
   ├─ 그림판.js                  # 캔버스 그리기 (마우스 + 터치)
   ├─ 전처리.js                  # preprocess.py 이식
   ├─ 모델.js                    # 가중치 적재 + 순전파
   ├─ 앱.js                      # 위 셋을 엮어 결과 표시
   ├─ 가중치.bin                 # 산출물 약 4.6MB — 커밋한다
   ├─ 가중치정보.json            # 산출물 — 커밋한다
   ├─ 검증데이터.json            # 산출물 — gitignore 대상

```

파이썬 파일 이동은 `git mv` 로 수행해 이력을 보존한다. 다섯 파일 모두 같은 폴더에 함께 이동하므로 상대 임포트(`from model import MnistCNN` 등)는 수정할 필요가 없다.

`.gitignore` 의 기존 규칙 `data/` 와 `*.pt` 는 하위 폴더에도 그대로 적용되므로 이동한 파일들은 계속 제외된다. `가중치.bin` 은 어떤 기존 규칙에도 걸리지 않으므로 그대로 커밋된다. 추가할 규칙은 `web_version/검증데이터.json` 한 줄이다.

### 2.1 이동 후 실행 위치

`train.py` 는 상대 경로 `data` 를, `draw_app.py` 와 `predict.py` 는 상대 경로 `mnist_cnn.pt` 를 기본값으로 쓴다. 따라서 이동 후에는 **`desktop_version/` 안에서 실행해야 한다.** 코드를 고치는 대신 이 사실을 `desktop_version/CLAUDE.md` 에 적는다. "내용 변경 없이 이동"이라는 원칙을 지키기 위함이다.

## 3. 문서 3개의 역할 분담

| 파일 | 담는 내용 | 담지 않는 내용 |
| --- | --- | --- |
| 루트 `CLAUDE.md` | 한글 이름 관례, 두 폴더의 관계, 가중치 흐름, 폴라리티/정규화 불변식 | 각 버전의 세부 실행법 |
| `desktop_version/CLAUDE.md` | 기존 CLAUDE.md 의 PyTorch 내용, `state_dict` 키 주의, 학습·실행 명령, **2.1의 실행 위치 제약**, 내보내기·검증데이터 절차 | 자바스크립트 관련 내용 |
| `web_version/CLAUDE.md` | 순수 JS 제약, `.bin` 레이아웃 계약, 전처리에서 파이썬과 맞춰야 할 지점, `file://` 문제, 검증 절차와 기준, ONNX를 쓰지 않은 이유, Pages 배포 | 파이썬 관련 내용 |

하위 폴더 `CLAUDE.md` 는 해당 폴더의 파일을 다룰 때 로드되고 루트는 항상 로드된다. 따라서 공통 사항은 루트에만 두고 하위에서 반복하지 않는다.

## 4. 가중치 전달 계약

이 계약이 두 버전을 잇는 유일한 인터페이스이므로 양쪽 CLAUDE.md 에 명시적으로 기록한다.

### 4.1 `가중치.bin`

8개 텐서를 아래 순서로 float32 리틀엔디언으로 연속 기록한다. 헤더도 구분자도 없다.

| 순서 | 텐서 | 형상 | 개수 | 시작(float 단위) |
| --- | --- | --- | --- | --- |
| 1 | `합성곱1.weight` | [32, 1, 3, 3] | 288 | 0 |
| 2 | `합성곱1.bias` | [32] | 32 | 288 |
| 3 | `합성곱2.weight` | [64, 32, 3, 3] | 18432 | 320 |
| 4 | `합성곱2.bias` | [64] | 64 | 18752 |
| 5 | `완전연결1.weight` | [128, 9216] | 1179648 | 18816 |
| 6 | `완전연결1.bias` | [128] | 128 | 1198464 |
| 7 | `완전연결2.weight` | [10, 128] | 1280 | 1198592 |
| 8 | `완전연결2.bias` | [10] | 10 | 1199872 |

합계 1,199,882개 = 4,799,528바이트(약 4.6MB). 각 텐서 내부의 원소 순서는 PyTorch 의 C 연속(row-major) 순서를 그대로 따른다.

엔디언은 `astype("<f4")` 로 명시한다. 플랫폼 기본값에 의존하지 않는다.

> **참고: 수업 노트와 크기가 다른 이유**
> 수업 노트(3.5.4 d)는 421,642 파라미터 / 1,686,568바이트로 적고 있다. 역산하면 그 모델은 `완전연결1` 입력이 3136(= 64×7×7)이므로 풀링이 2개다. 우리 `model.py` 는 풀링이 1개여서 입력이 9216(= 64×12×12)이고, 그 결과 파라미터가 약 2.8배 많다. 노트도 "실습실에서는 항목 수와 내용이 다를 수 있음"이라고 밝히고 있다. 위 표가 **우리 코드 기준의 정답**이며, 구현 시 실제 값으로 다시 확인한다.

### 4.2 `가중치정보.json`

```json
{
  "정규화": { "평균": 0.1307, "표준편차": 0.3081 },
  "텐서들": [
    { "이름": "합성곱1.weight", "형상": [32, 1, 3, 3], "시작": 0, "개수": 288 }
  ]
}
```

`모델.js` 는 4.1의 표를 하드코딩하지 않고 이 파일을 읽어 `.bin` 을 잘라 쓴다. 정규화 상수도 `preprocess.py` 에서 읽어 여기에 싣는다. 값의 출처를 파이썬 하나로 유지하기 위함이며, 이로써 `평균`/`표준편차` 중복은 파이썬 쪽 두 곳(`train.py`, `preprocess.py`)에 그대로 남고 웹으로는 번지지 않는다.

### 4.3 평탄화 순서

PyTorch `x.flatten(1)` 은 (64, 12, 12) 텐서를 채널 우선으로 편다. 자바스크립트도 반드시 같은 식을 써야 한다.

```
색인 = 채널 * 144 + 세로 * 12 + 가로
```

이 순서가 틀리면 오류 없이 예측만 무의미해진다. 검증이 잡아내는 대표적 오류다.

## 5. 데스크톱 신규 스크립트

### 5.1 `가중치내보내기.py`

```
python 가중치내보내기.py [--가중치 mnist_cnn.pt] [--출력폴더 ../web_version]
```

1. `torch.load(..., map_location="cpu")` 로 `state_dict` 를 읽는다.
2. 기대하는 8개 키가 모두 있는지 확인한다. 하나라도 없으면 어떤 키를 찾았고 무엇을 기대했는지 보여 주며 중단한다. 계층 이름을 바꿔 체크포인트가 무효가 된 상황을 조용한 오작동이 아니라 명시적 오류로 드러내기 위함이다.
3. 각 텐서의 형상이 4.1의 표와 일치하는지 확인한다.
4. `가중치.bin` 과 `가중치정보.json` 을 쓴다. 정규화 상수는 `preprocess.py` 에서 임포트해 싣는다.
5. 기록한 텐서 수, 총 파라미터 수, 파일 크기를 출력한다.

### 5.2 `검증데이터만들기.py`

```
python 검증데이터만들기.py [--개수 200] [--손그림 30] [--씨앗 1]
                          [--출력 ../web_version/검증데이터.json]
```

두 종류의 표본을 만든다. 각 사례마다 280×280 원본(무손실 PNG → base64), 파이썬 전처리 결과(실수 784개), 파이썬 확률(10개), 정답 라벨을 기록한다.

**종류 A — 정격 표본 (기본 200장)**
MNIST 테스트 이미지를 NEAREST 로 정확히 10배(28 → 280) 확대한다. 파이썬과 자바스크립트가 완전히 동일한 화소에서 출발하므로 경로 차이만 순수하게 드러난다.

**종류 B — 변형 표본 (기본 30장)**
종류 A만으로는 부족하다. 정수배 확대만 쓰면 경계 상자 크기가 항상 10의 배수로 떨어져, **비정수 배율 · 안티에일리어싱된 획 가장자리 · 캔버스 가장자리 접촉**을 한 번도 시험하지 못한다. 수업 노트 3.5.7 c) 9번이 바로 이 빈틈을 지적하며, 실제로 "무엇을 그려도 0이라고 답하던 결함"을 검증이 그대로 통과시킨 사례를 기록하고 있다.

따라서 종류 B는 MNIST 이미지를 **비정수 배율(7.0~11.9배 중 무작위)로 BILINEAR 확대**하고 **무작위 위치**(일부는 캔버스 가장자리에 닿도록)에 배치한다. 씨앗을 고정해 재현 가능하게 한다.

정답 데이터를 구현보다 먼저 만든다. 검사 수단을 먼저 두고 그것을 통과하도록 구현하기 위함이다.

`검증데이터.json` 은 `.gitignore` 대상이다.

## 6. 웹 버전 구성 요소

네 파일이 각각 하나의 일만 하고 ES 모듈로 값만 주고받는다. 전역 변수를 공유하지 않는다.

### 6.1 `전처리.js`

```
전처리(명도배열, 너비, 높이, 정규화상수) → Float32Array(784) | null
```

`preprocess.py` 의 3단계를 그대로 옮긴다.

1. 0이 아닌 화소의 경계 상자를 찾아 잘라낸다 (PIL `getbbox()` 상당). 없으면 `null` 을 돌려준다.
2. 가로세로 비율을 유지하며 긴 변이 20px이 되도록 축소하고, 28×28 검은 바탕 중앙에 놓는다.
3. 명도를 무게로 보아 무게중심을 구하고 (13.5, 13.5)로 정수만큼 평행이동한다. 바깥은 0으로 채운다.

이어서 `(값 / 255 - 평균) / 표준편차` 로 정규화한다. 정규화 상수는 인자로 받으며 파일 안에 적지 않는다.

**파이썬과 다른 단 한 곳은 축소 방식이다.** `preprocess.py` 는 PIL 의 LANCZOS 를 쓰지만 웹은 **면적 평균 축소**를 직접 구현한다. 출력 화소 하나가 덮는 입력 영역을 부분 겹침까지 고려해 가중 평균한다. LANCZOS 이식도 가능하지만, 수업 노트가 면적 평균으로 정확도 98.0%를 실측했으므로 더 단순한 쪽을 택한다. 7.2의 정확도 기준을 통과하지 못하면 그때 LANCZOS 이식을 검토한다.

면적 평균 구현 시 주의: 배율을 부동소수점으로 계산하면 경계 좌표가 `19 * (21/19) = 21.000000000000004` 처럼 아주 조금 넘칠 수 있고, 이 값이 배열 밖을 읽게 만든다. 수업 노트 3.5.7 b)가 기록한 실제 결함이다. 경계 색인은 입력 크기로 잘라내야 한다.

### 6.2 `모델.js`

```
모델불러오기(가중치정보URL, 가중치URL) → { 추론, 정규화상수 }
추론(입력784) → Float32Array(10)   // 확률
```

`가중치정보.json` 을 읽고 `가중치.bin` 을 `ArrayBuffer` 로 받아 텐서별 `Float32Array` 뷰로 자른다. 순전파는 `model.py` 의 `forward` 와 같은 순서로 수행하고, 드롭아웃은 추론 시 아무 일도 하지 않으므로 생략한다. 마지막에 소프트맥스를 적용해 확률을 돌려준다.

연산은 소박한 중첩 루프로 구현한다. 전체 연산량이 약 1,200만 MAC이므로 브라우저에서 수 밀리초면 끝난다. 최적화는 넣지 않는다.

구현 시 주의 두 가지 (수업 노트 3.5.7 c)의 1·2번):

- `가중치.bin` 의 `byteLength` 가 4의 배수인지 먼저 검사한다. 아니면 `new Float32Array()` 가 네이티브 `RangeError` 를 던져 원인이 드러나지 않는다.
- 소프트맥스에서 `Math.max(...배열)` 로 스택을 펼치지 않는다. 지금은 원소가 10개라 안전하지만 큰 텐서에 재사용하면 터진다. 반복문으로 최댓값을 구한다.

### 6.3 `그림판.js`

280×280 캔버스에 검은 배경·흰 선, 선굵기 18로 그린다. 데스크톱 `draw_app.py` 와 같은 값이다.

- Pointer Events 하나로 마우스·터치·펜을 모두 받는다.
- 캔버스는 CSS로 화면 폭에 맞춰 축소하되 **내부 해상도는 280으로 고정**하고, 포인터 좌표를 `getBoundingClientRect()` 비율로 변환한다. 이 변환을 빠뜨리면 큰 화면에서는 정상인데 좁은 화면에서만 선이 어긋난다.
- 캔버스에 `touch-action: none` 을 지정해 그리는 동안 페이지가 스크롤되지 않게 한다.
- 포인터를 떼면 인식 콜백을 호출한다 (`draw_app.py` 의 동작과 동일).

### 6.4 `앱.js`

위 셋을 엮고 화면을 갱신한다. 모델과 전처리의 내부는 모른다.

```
포인터 입력 → 280×280 캔버스
  → getImageData → 명도 배열
  → 전처리.js → Float32Array(784)
  → 모델.js 추론 → 확률 10개
  → 상위 3개 후보 표시
```

기능 범위는 데스크톱과 같게 하고 터치 입력만 더한다. 두 버전 비교가 목적이므로 기능 차이를 두지 않는다. 검토했으나 채택하지 않은 것: 28×28 전처리 미리보기(전처리 확인은 `검증.html` 이 맡는다), 확률 10개 전체 표시(화면이 길어진다).

가중치 적재 중에는 그리기를 막고 진행 상태를 표시한다. 적재가 끝나면 그 사이 그려 둔 그림이 있으면 자동으로 한 번 인식한다 (수업 노트 3.5.7 c)의 7번).

## 7. 검증

### 7.1 `검증.html`

`검증데이터.json` 을 읽어 사례마다 두 갈래를 독립적으로 돌린다.

- **순전파 갈래** — 파이썬이 기록한 전처리 결과(784개)를 그대로 `모델.js` 에 넣어 확률을 파이썬 확률과 비교한다. 전처리와 무관하게 순전파만 격리해 검사한다.
- **전체 갈래** — `원본PNG` 를 캔버스로 디코딩(무손실이므로 화소가 정확히 일치) → `전처리.js` → `모델.js` → 예측을 정답 라벨과 비교해 정확도를 낸다.

결과를 종류 A/B 별로 나누어 표시한다. 사례별 표(`확률 최대차` / `전처리 최대차` / `예측` / `정답`)와 전체 요약(순전파 최대차, 파이썬 정확도, 자바스크립트 정확도)을 보여 준다. 외부 라이브러리 없이 DOM 조작만 쓴다.

전처리가 `null` 을 돌려주는 사례가 있어도 조기 반환하지 않고 실패로 집계한 뒤 끝까지 진행해, 요약 줄이 항상 나오게 한다 (수업 노트 3.5.7 c)의 4번). 정규화 식을 검증 페이지에 다시 적지 않고 `전처리.js` 의 것을 임포트해 쓴다 (같은 항목 3번).

### 7.2 합격 기준

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 순전파 확률 | 최대 절대차 ≤ 1e-4 | 전처리를 배제한 순수 순전파 일치. 수업 노트 실측은 2.68e-7이었다 |
| 전체 정확도 | 97% 이상 | 수업 노트와 같은 기준 |
| 파이썬 대비 | 파이썬 정확도보다 1%p 넘게 낮지 않을 것 | 절대 기준만 쓰면 파이썬 자체가 낮을 때 이식 오류가 묻힌다 |
| 종류 B | 종류 B만 따로 봐도 위 두 기준을 만족 | 변형 표본이 정격 표본에 묻히지 않게 한다 |

정확도로 판정하는 방식의 한계를 분명히 해 둔다. 검증 통과는 "옳다"가 아니라 **"시험해 본 범위 안에서는 옳다"**는 뜻이다. 종류 B를 넣는 것도 시험 범위를 넓히려는 조치이지 완전성을 보장하지 않는다.

### 7.3 검증 데이터를 커밋하지 않는 이유

검증은 개발 시점 활동이고 최종 사용자에게 필요 없다. `검증데이터.json` 은 `.gitignore` 대상이며, 따라서 **`검증.html` 은 GitHub Pages 에서는 동작하지 않고 로컬에서만 동작한다.** 파일이 없을 때는 `python 검증데이터만들기.py` 를 먼저 실행하라는 안내를 표시한다.

## 8. 오류 처리

조용한 실패를 만들지 않는 데 초점을 둔다.

| 상황 | 동작 |
| --- | --- |
| `가중치.bin` 또는 `가중치정보.json` 적재 실패 | 그리기를 막고 한글 안내 표시 |
| `.bin` 의 `byteLength` 가 4의 배수가 아님 | 명시적 오류. 네이티브 `RangeError` 로 원인이 묻히는 것을 막는다 |
| `가중치정보.json` 의 총 개수 × 4 ≠ `.bin` 바이트 수 | 즉시 오류. 두 산출물이 어긋난 채 동작하는 상황을 차단한다 |
| `file://` 로 연 경우 | ES 모듈이 CORS 로 차단되어 화면이 조용히 멈춘다. 이를 감지해 `python -m http.server` 로 열라고 안내한다 |
| 빈 그림 | `전처리` 가 `null` → "먼저 숫자를 그려 주세요" |
| `검증데이터.json` 없음 | `python 검증데이터만들기.py` 실행 안내 |

`file://` 안내는 필수다. 로컬에서 `index.html` 을 더블클릭하면 반드시 실패하는데 원인이 화면에 드러나지 않으면 막힌다. 다만 `file://` 에서 `error` 이벤트가 실제로 발화하는지는 브라우저에서 직접 확인한 뒤 방식을 정한다 (수업 노트 3.5.7 c)의 8번이 미확인으로 남긴 항목).

## 9. 배포

`.github/workflows/pages.yml` 이 `main` 브랜치 푸시 때 `web_version/` 을 그대로 Pages 에 올린다. `actions/configure-pages` → `actions/upload-pages-artifact` (`path: web_version`) → `actions/deploy-pages` 순서이며 빌드도 npm 도 없다. 권한은 `pages: write`, `id-token: write` 를 준다.

`index.html` 이 저장소 최상위가 아니라 `web_version/` 안에 있으므로 Pages 의 기본값인 "Deploy from a branch" 로는 동작하지 않는다. Source 를 **GitHub Actions** 로 바꿔야 한다.

원격 저장소는 `https://github.com/nk0101-del/Study01_MNIST.git` 로 이미 연결되어 있다.

**Source 변경 방법**: 수업 노트 3.5.8.3은 Claude 가 GitHub CLI(`gh`)로 바꾸는 방법을 안내하지만, **이 컴퓨터에는 `gh` 가 설치되어 있지 않다.** 둘 중 하나로 처리한다.

1. 저장소 페이지 → Settings → Pages → Build and deployment → Source 에서 **GitHub Actions** 를 직접 선택 (저장소당 1번)
2. `gh` 를 설치하고 로그인한 뒤 Claude 가 설정

배포는 몇 분 걸린다. 중간에 취소하고 다시 누르지 않는다.
